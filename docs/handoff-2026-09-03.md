## 1. 项目概况

儿童行为管理 PWA，目标用户 5 岁女孩。核心闭环：**任务打卡 → 赚积分 → 养宠物 + 兑换奖励**。

### 技术栈

| 类别 | 选型 |
|------|------|
| 框架 | React 18 + TypeScript 7 + Vite 8 |
| 样式 | Tailwind CSS v4（`@tailwindcss/vite` 插件，无 PostCSS） |
| 状态管理 | Zustand 5 |
| 持久化 | Dexie.js 4（IndexedDB），数据库版本 v2 |
| 动画 | Framer Motion 13 |
| 图标 | @phosphor-icons/react |
| PWA | vite-plugin-pwa（autoUpdate 模式 + `navigator.storage.persist()`） |

### 架构

Clean Architecture 四层，61 个源文件：

```
src/
├── domain/           # 纯 TS class，零外部依赖
│   ├── models/       # Task, Reward, Pet, PointBalance, TaskLog, RewardLog
│   ├── valueObjects/ # PetStage
│   ├── repositories/ # 接口（ITaskRepository, IRewardRepository, IBackupAdapter 等）
│   └── rules/        # 业务规则（TaskResetRule, PetGrowthRule, HungerRule, DateUtils 等）
├── infrastructure/   # Dexie 实现 + JSON 备份适配器
├── application/      # Service 层（TaskService, RewardService, PointService, PetService, BackupService）
├── presentation/     # React 页面 + 组件 + Zustand store
│   ├── pages/        # Home, TaskCheckin, TaskManage, Shop, Pet, Settings
│   ├── layouts/      # TabBar
│   ├── hooks/        # useTaskStore, useRewardStore, usePetStore 等
│   └── components/   # LoadingFallback
└── shared/           # constants.ts（DEFAULT_CHILD_ID, REWARD_CATEGORIES, ROUTES）
```

## 5. 关键技术上下文

### CSS Cascade Layers

Tailwind v4 的 Preflight (base layer) 会重置表单元素样式。**解决方案**：表单元素（`<input>` / `<select>`）使用 inline `style` 而非 Tailwind className。已在 `TaskEditModal.tsx` 和 `RewardEditModal.tsx` 中实施。

### Dexie 数据库

版本 v2，`tasks` 表有复合索引 `[childId+isActive]` 和 `[childId+type]`。修改 schema 须升级版本号。

### iPad 响应式

- CSS 变量 `--app-max-width`：默认 480px / 768px+ 680px / 1024px+ 800px
- TabBar 宽度跟随 `var(--app-max-width)`
- 弹窗组件在 `md:768px+` 有加宽断点
- 首页**保持单列**（双栏方案已被用户否决）

### 任务系统特殊逻辑

- **取消完成（uncomplete）**：不同类型删除不同范围的 log（daily 删当天/weekly 删本周/one-time 删最后一条/negative 删当天全部）
- **积分回退**：uncomplete 时自动回退积分（正分扣回/扣分还回）
- **扣分行为**：前端不区分，后端根据 `task.points` 正负自动走 `earn` / `deduct`
- **防抖**：`processing` 状态锁 + `disabled` 防止快速连续点击

### 路由懒加载

所有 6 个页面（Home/TaskCheckin/TaskManage/Shop/Pet/Settings）使用 `React.lazy()` + `<Suspense>`，`LoadingFallback` 组件显示加载动画。

## 8. Grill Me 发现（2026-09-03 任务模块深度讨论）

### 确认正确的设计

| 项 | 结论 |
|----|------|
| 每日任务 | 每天可完成一次，次日自动重置（隐式），任务永久存在 |
| 每周任务 | 一周一次，周一重置 |
| 扣分行为 | = DAILY + 负积分，一天一次 |
| 统计 | 打卡页显示今日净积分，其他模块显示总余额 |
| 数据模型 | TaskLog 事件流够用，后续做日历热力图时加聚合方法 |
| 分区顺序 | 每日 → 每周 → 一次性 → 扣分 |
| 任务字段 | title/type/points/icon 已完整 |
| 删除 vs 积分 | 删除任务不影响已获积分 |

### 发现的 Bug（待修复）

| # | 问题 | 当前行为 | 预期行为 | 修复方向 |
|---|------|---------|---------|---------|
| G1 | 一次性任务完成后永远显示 | 完成后永久在列表中 | 完成当天显示✅，次日消失 | 过滤：`isOneTime && completed && completedAt < todayStart` 则不展示 |
| G2 | 首页「今日任务」显示类型错误 | 显示 DAILY + NEGATIVE | 应显示 DAILY + WEEKLY + ONE_TIME（不含 NEGATIVE） | 修改 `todayTasks` 过滤条件 |
| G3 | 「待完成」统计虚高 | 包含已过期的 ONE_TIME | 只算今天可完成的未完成任务 | 与 G1 联动，排除已完成的 ONE_TIME |
| G4 | 任务硬删除 | `TaskService.deleteTask` 直接删除记录 | 应软删除（`deactivate`） | 改用 `task.deactivate()` + `save()` |
