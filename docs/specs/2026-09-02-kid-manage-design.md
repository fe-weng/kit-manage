## 1. 产品概述

### 1.1 产品定位

一款面向家长的儿童行为管理工具，通过「任务 → 积分 → 养成 + 兑换」的闭环，帮助家长引导孩子建立良好行为习惯。

### 1.2 目标用户

| 维度 | 说明 |
|------|------|
| **操作者** | 家长（爸爸/妈妈） |
| **受益者** | 5 岁女孩（孩子不直接操作 App） |
| **使用场景** | 家庭内部，家长设置任务并确认完成，孩子通过虚拟宠物和奖励获得正向激励 |

### 1.3 核心价值

```
家长设置任务 → 孩子完成行为 → 家长确认 → 获得积分
                                              ↓
                                    喂养宠物（养成乐趣）
                                              +
                                    兑换奖励（现实激励）
```

## 2. 技术架构

### 2.1 技术栈

| 层级 | 选择 | 理由 |
|------|------|------|
| **框架** | React 18 + TypeScript | 开发者熟悉，生态成熟 |
| **构建工具** | Vite | 开发体验好，构建快 |
| **样式方案** | Tailwind CSS | 灵活，适合自定义 UI（宠物/养成场景） |
| **基础组件库** | Ant Design Mobile (antd-mobile) | 提供按钮/弹窗/列表等基础移动端组件 |
| **状态管理** | Zustand | 轻量简洁 |
| **本地存储** | Dexie.js (IndexedDB) | IndexedDB 的友好封装，支持复杂查询和事务 |
| **动画** | Framer Motion | React 动画库，宠物状态切换和互动动画 |
| **路由** | React Router (BrowserRouter) | 使用 History 模式，URL 更美观，Vercel 部署 |
| **离线支持** | Service Worker (PWA) | 缓存静态资源，支持离线使用 |

### 2.2 平台与分发

| 维度 | 方案 |
|------|------|
| **产品形态** | PWA（渐进式 Web App） |
| **主要终端** | iPad（也兼容手机浏览器） |
| **部署方式** | Vercel 免费托管，自动分配子域名 |
| **安装方式** | iPad Safari → 分享 → 添加到主屏幕 |
| **离线能力** | Service Worker 缓存，离线可用 |
| **费用** | $0（全部使用免费方案） |

### 2.3 数据存储策略

| 策略 | 说明 |
|------|------|
| **主存储** | IndexedDB（通过 Dexie.js 操作） |
| **持久化** | 调用 `navigator.storage.persist()` 请求浏览器不自动清除数据 |
| **备份** | 提供导入/导出 JSON 功能，用户可手动备份 |
| **多设备** | MVP 不支持自动同步，通过导入/导出 JSON 手动迁移数据 |

### 2.4 分层架构

采用 **Clean Architecture / DDD-lite** 分层架构，模拟真实后端项目结构。

#### 架构全景

```
┌──────────────────────────────────────────────────────┐
│                  Presentation Layer                   │
│             （React 组件 / Hooks / Pages）             │
│     只负责 UI 渲染和用户交互，不含业务逻辑              │
└───────────────────────┬──────────────────────────────┘
                        │ 调用 Service
                        ▼
┌──────────────────────────────────────────────────────┐
│                  Application Layer                    │
│              （Service / Use Cases）                  │
│     编排业务流程，调用 Domain 和 Repository             │
│                                                      │
│  TaskService  PetService  PointService  RewardService│
└───────────────────────┬──────────────────────────────┘
                        │ 使用 Domain Model + Repository 接口
                        ▼
┌──────────────────────────────────────────────────────┐
│                    Domain Layer                       │
│            （核心业务逻辑，零外部依赖）                 │
│                                                      │
│  Models:  Task / Pet / Reward / PointBalance          │
│  Rules:   PetGrowthRule / TaskResetRule / HungerRule  │
│  Interfaces:  ITaskRepo / IPetRepo / IPointRepo      │
└───────────────────────┬──────────────────────────────┘
                        │ Repository 接口（依赖反转）
                        ▼
┌──────────────────────────────────────────────────────┐
│                Infrastructure Layer                   │
│            （具体技术实现，可替换）                     │
│                                                      │
│  DexieTaskRepository implements ITaskRepo             │
│  DexiePetRepository  implements IPetRepo              │
│  DexieDatabase (IndexedDB via Dexie.js)              │
│  JsonBackupAdapter / ServiceWorkerManager            │
└──────────────────────────────────────────────────────┘
```

#### 依赖方向（关键原则）

```
Presentation → Application → Domain ← Infrastructure
```

- **Domain 层是核心**，不依赖任何外层。
- **Repository 接口**定义在 Domain 层，**实现**在 Infrastructure 层（依赖反转）。
- 将来如果接入真实后端 API，只需替换 Infrastructure 层的 Repository 实现，其他层完全不变。

### 2.6 依赖注入

使用简单的手动依赖注入容器，将各层连接：

```typescript
// shared/container.ts
const db = new KidManageDB()

// Infrastructure 层：Repository 实现
const taskRepo = new DexieTaskRepository(db)
const petRepo = new DexiePetRepository(db)
const pointRepo = new DexiePointRepository(db)
const rewardRepo = new DexieRewardRepository(db)

// Application 层：Service（注入 Repository 接口）
export const pointService = new PointService(pointRepo)
export const taskService = new TaskService(taskRepo, pointService)
export const petService = new PetService(petRepo, pointService)
export const rewardService = new RewardService(rewardRepo, pointService)
export const backupService = new BackupService(db)
```

## 3. 功能设计

### 3.1 任务系统

#### 任务类型

| 类型 | 说明 | 积分 | 刷新规则 |
|------|------|------|---------|
| **每日任务** | 每天重复的行为习惯 | 家长自定义（正分） | 每天 00:00 自动刷新为未完成 |
| **每周任务** | 每周完成的目标 | 家长自定义（正分） | 每周一 00:00 自动刷新 |
| **一次性任务** | 临时设置的任务 | 家长自定义（正分） | 完成后从任务列表移除 |
| **扣分行为** | 记录不良行为 | 家长自定义（负分） | 手动触发，记录一次扣一次 |

#### 任务操作

- **查看/完成任务**：在「今日打卡」页面，点击任务即可标记完成（家长操作）
- **创建任务**：在「任务管理」页面，点击「+ 新增」→ 弹出居中 Modal，填写名称、类型、积分值
- **编辑任务**：在「任务管理」页面，点击任务行的「>」→ 弹出编辑 Modal，修改名称、积分值、类型
- **删除任务**：在编辑 Modal 底部，点击红色「🗑️ 删除任务」按钮
- **扣分记录**：在「今日打卡」页面底部，点击扣分按钮即可快捷记录一次扣分

#### 任务数据模型

```typescript
interface Task {
  id: string
  childId: string            // 预留多孩子扩展
  title: string              // 任务名称
  type: 'daily' | 'weekly' | 'oneTime' | 'negative'
  points: number             // 积分值（负数表示扣分）
  icon?: string              // 任务图标（可选）
  createdAt: number          // 创建时间戳
  isActive: boolean          // 是否启用
}

interface TaskLog {
  id: string
  taskId: string
  childId: string
  completedAt: number        // 完成时间戳
  pointsEarned: number       // 实际获得的积分
  type: 'earn' | 'deduct'    // 获取或扣除
}
```

### 3.2 宠物养成系统

#### 核心循环

```
完成任务 → 获得积分 → 花积分买食物 → 喂宠物 → 宠物成长 → 解锁新阶段/新宠物
```

#### 成长阶段

| 阶段 | 名称 | 所需经验值 | 视觉表现 |
|------|------|-----------|---------|
| 1 | 神秘蛋 | 0 | 一颗彩色的蛋（带花纹和微光） |
| 2 | 刚孵化 | 50 EXP | 圆滚滚的小动物，蛋壳碎片在头上，大眼睛 |
| 3 | 成长期 | 200 EXP | 长出特征（翅膀/耳朵），戴配饰（蝴蝶结/围巾），有腮红 |
| 4 | 成熟期 | 500 EXP | 完全体形态，优雅自信，戴小皇冠/花环 |
| 5 | 满级 | 1000 EXP | 金色光环/星光闪烁，最华丽装饰，可解锁下一只 |

> 喂食一次 = 获得一定经验值（EXP），EXP 累计推动阶段成长。

#### 宠物列表与视觉风格

| # | 宠物 | 主色调 | 特点 |
|---|------|--------|------|
| 1 | 🐔 小鸡 | 暖黄 + 粉色 | 圆润活泼，腮红，蝴蝶结 → 小皇冠 → 金色闪光 |
| 2 | 🐰 小兔子 | 白色 + 薰衣草紫 | 长耳朵，粉鼻子，小裙子 → 花环 → 彩虹耳朵 + 魔法杖 |

> **视觉风格要求（⚠️ 关键）**：
> - **卡通 Q 版**风格，禁止写实！
> - 头大身小（SD/Chibi 比例），整体圆润
> - 大而闪亮的眼睛，丰富的表情
> - 柔和糖果色系，与 Claymorphism UI 风格一致
> - 目标受众：5 岁女孩，核心感受「好可爱！我想养它！」
> - 素材可通过 AI 生成（Midjourney/DALL-E）或插画师绘制
> - MVP 阶段可用简单占位图，但需保持 Q 版比例

#### 互动功能

| 功能 | MVP | 说明 |
|------|-----|------|
| **抚摸** | ✅ | 触摸宠物 → 播放开心动画（摇尾巴、跳跃、爱心冒出） |
| **喂食** | ✅ | 花费积分购买食物 → 点击喂食 → 宠物吃东西动画 → 获得 EXP |
| 对话气泡 | 🔜 | 宠物随机冒出气泡（"我饿了"、"今天真棒"） |
| 换装 | 🔜 | 给宠物穿衣服/戴帽子 |
| 小游戏 | 🔜 | 和宠物玩简单小游戏 |
| 场景互动 | 🔜 | 宠物在场景里走动、睡觉 |

#### 状态系统

| 状态 | 计算方式 | 影响 |
|------|---------|------|
| **饥饿度** | 每天未喂食 → 饥饿度增加 | 饥饿度高 → 宠物显示饿了的表情 |
| **心情** | 完成任务多 → 开心；扣分多 → 难过 | 影响宠物的表情和动画 |
| **成长值 (EXP)** | 喂食累计 | 达到阈值 → 进化到下一阶段 |

#### 宠物数据模型

```typescript
interface Pet {
  id: string
  childId: string
  name: string               // 宠物名称（可自定义）
  type: string               // 宠物种类
  stage: 1 | 2 | 3 | 4 | 5  // 当前成长阶段
  exp: number                // 当前经验值
  hunger: number             // 饥饿度（0-100，0=饱，100=很饿）
  mood: number               // 心情值（0-100，0=很伤心，100=很开心）
  lastFedAt: number          // 上次喂食时间戳
  createdAt: number
}
```

### 3.3 奖励商城

interface Reward {

### 3.4 积分系统

#### 积分流向

```
积分来源                          积分消耗
├── 完成每日任务 +N    ──→    ├── 喂养宠物 -N（转化为 EXP）
├── 完成每周任务 +N    ──→    └── 兑换奖励 -N
├── 完成一次性任务 +N
└── 扣分行为 -N
```

#### 积分数据模型

```typescript
interface PointBalance {
  childId: string
  totalEarned: number        // 累计获得总积分
  totalSpentOnPet: number    // 喂宠物花费的总积分
  totalSpentOnReward: number // 兑换奖励花费的总积分
  currentBalance: number     // 当前可用积分 = earned - spentPet - spentReward
}
```

### 3.5 数据管理

#### 导出

- 将所有数据（任务、宠物、积分、日志）序列化为 JSON
- 下载为 `.json` 文件
- 文件名包含日期：`kid-manage-backup-2026-09-02.json`

#### 导入

- 选择 JSON 文件上传
- 校验数据格式
- 确认对话框提示「导入将覆盖当前数据」
- 导入完成后刷新界面

## 6. 数据库设计

### 6.1 Dexie.js 数据库定义

```typescript
// infrastructure/database/DexieDatabase.ts
import Dexie, { type Table } from 'dexie'

export class KidManageDB extends Dexie {
  children!: Table
  tasks!: Table
  taskLogs!: Table
  pets!: Table
  rewards!: Table
  rewardLogs!: Table

  constructor() {
    super('kid-manage')
    this.version(1).stores({
      children: 'id, name',
      tasks: 'id, childId, type, isActive',
      taskLogs: 'id, taskId, childId, completedAt',
      pets: 'id, childId',
      rewards: 'id, isPreset, isActive',
      rewardLogs: 'id, rewardId, childId, redeemedAt',
    })
  }
}
```

> 注意：数据库定义位于 `infrastructure/` 层，Domain 层通过 Repository 接口访问数据，不直接依赖 Dexie。

### 6.2 数据关系

```
Child (1) ──→ (N) Task
Child (1) ──→ (N) TaskLog
Child (1) ──→ (1) Pet
Child (1) ──→ (N) RewardLog
Reward (1) ──→ (N) RewardLog
Task (1) ──→ (N) TaskLog
```

## 7. MVP 范围

### 7.1 MVP 包含

| 模块 | 功能 |
|------|------|
| **任务系统** | 每日/每周/一次性/扣分 四种类型，自定义积分，点击完成 |
| **宠物系统** | 5 阶段成长，喂食 + 抚摸互动，饥饿度/心情状态 |
| **奖励商城** | 系统预设 + 自定义奖励，积分兑换 |
| **积分系统** | 积分获取/消耗/余额管理 |
| **数据管理** | 导入/导出 JSON 备份 |
| **PWA** | 添加到主屏幕，离线缓存 |

### 7.2 MVP 不包含（后续迭代）

| 优先级 | 功能 | 说明 |
|--------|------|------|
| P1 | 统计报表 | 周/月完成情况图表 |
| P1 | 历史记录 | 任务完成和兑换记录查询 |
| P2 | 日历视图 | GitHub 绿格子风格的完成日历 |

| P2 | 宠物换装 | 给宠物穿衣服/配饰 |
| P3 | 装扮卧室 | 替代养成方案：预设槽位装扮房间 |
| P3 | 挑战任务 | 连续达标类任务 |
| P3 | 宠物小游戏 | 和宠物玩简单小游戏 |

## 8. 设计决策记录

| 编号 | 决策 | 理由 |
|------|------|------|
| D1 | 仅家长端，无孩子端 | 孩子才 5 岁，不需要独立操作 App |
| D2 | 本地存储而非 BaaS | 用户不想依赖云服务，通过导入/导出解决多设备需求 |
| D3 | PWA 而非 Capacitor | 目标终端 iPad，不想花 $99 Apple 开发者费用，PWA 零成本 |
| D4 | 先做宠物养成，房间装扮保留 | 宠物有更强的情感联结和持续动力 |
| D5 | 所有积分家长自定义 | 不同家庭对同一行为的重视程度不同 |
| D6 | 任务确认为简单点击 | MVP 最小化，不增加操作负担 |
| D7 | 挑战任务延后 | 机制复杂，MVP 先验证核心循环 |
| D8 | 单孩子但数据模型预留 childId | 方便后续扩展多孩子支持 |
| D9 | BrowserRouter（Vercel 部署） | URL 更美观，部署在 Vercel 无需 file:// 兼容 |
