# Kid Manage — 多宠物养成设计规范

> **版本**：v1.1  
> **日期**：2026-09-14  
> **状态**：需求已确认，实施任务已拆分  
> **关联文档**：[宠物进化设计规范](./2026-09-02-pet-design-spec.md)

---

## 1. 需求背景

当前系统以单个 `childId` 查询第一只宠物，只能持续喂养一只宠物。新方案需要在一只宠物满级后继续领养下一只，同时保留已经养成的宠物，并支持在首页和宠物页切换展示。

核心目标：

1. 保留每只宠物的养成结果，不覆盖旧宠物。
2. 同一时间只养成一只宠物，避免积分消耗与成长对象产生歧义。
3. 通过宠物图鉴统一承载收集、领养、改名和展示切换。
4. 兼容现有单宠物数据与旧版备份。

---

## 2. 核心业务规则

### 2.1 首次领养

- 第一只宠物继续免费领养。
- 沿用现有流程：选择宠物种类、填写名字、确认创建。
- 创建成功后，该宠物同时成为：
  - 当前养成宠物
  - 当前展示宠物

### 2.2 后续领养

- 当前唯一的养成中宠物达到第 5 阶段「满级」后，才解锁下一只宠物。
- 后续领养固定消耗 100 积分。
- 领养费用必须定义为领域常量：

```typescript
export const PET_ADOPTION_COST = 100
```

- 领养费用计入现有宠物消费总额，不新增积分流水或领养消费明细。
- 每个宠物种类只能领养一只。
- 当前仅有小鸡和小兔，因此最多拥有两只宠物。
- 同一时间最多存在一只未满级宠物。

### 2.3 领养校验与扣费

后续领养只能从宠物图鉴发起：

1. 当前养成宠物未满级时，不显示领养操作。
2. 当前养成宠物满级后，未领养卡显示「领养 100分」。
3. 点击领养时先检查积分：
   - 积分不足：提示“还差 N 分”，不打开表单。
   - 积分足够：打开命名弹窗。
4. 用户确认领养时再次校验积分，防止表单打开期间余额变化。
5. 二次校验成功后扣除 100 积分并创建宠物。
6. 用户取消命名弹窗时不扣积分。
7. 创建成功后，新宠物自动成为当前养成宠物和当前展示宠物。

### 2.4 宠物名称

- 名字不能为空。
- 名字最多 10 个字符。
- 不同宠物允许重名。
- 已领养宠物可以改名。

### 2.5 删除规则

- 不允许删除或放生单只宠物。
- 不退还领养积分或喂食积分。
- “重置所有数据”仍可清除全部宠物数据。

## 3. 展示宠物与养成宠物

多宠物模式下必须区分两个概念：

### 3.1 当前展示宠物

- 首页宠物卡、首页问候语和宠物展示页使用当前展示宠物。
- 任意已领养宠物都可以设为展示宠物。
- 展示选择通过宠物记录上的 `isDisplayed` 持久化，并纳入数据备份。
- 用户从图鉴点击「设为展示」后，保存选择并直接返回宠物展示页。

### 3.2 当前养成宠物

- 每只已领养宠物都是独立持久化记录，拥有自己的名字、种类、阶段、EXP 和心情。
- 当前唯一未满级的宠物即为当前养成宠物，不额外落库养成角色字段。
- 没有未满级宠物时，养成对象为空，允许领养下一只（若仍有未领养种类）。
- 只有当前养成宠物可以喂食、增加 EXP 和发生进化。
- 用户展示满级宠物且存在养成中宠物时，宠物页显示“正在养成”快捷卡。
- 点击快捷卡后，将养成中宠物设为展示宠物并切换到它。

### 3.3 满级宠物

- 满级宠物不再显示喂食功能，也不再增加 EXP。
- 满级宠物保留抚摸及其他非成长类互动。
- 满级后停止心情自然衰减。
- 抚摸仍可改变心情和触发互动动画。

## 4. 宠物图鉴

### 4.1 页面定位

- 新增独立路由：`/pet/collection`。
- 宠物图鉴是后续领养宠物的唯一入口。
- 图鉴页面保留底部五个 Tab，宠物 Tab 保持选中。
- 页面顶部提供返回宠物展示页的按钮。
- 设置页原“宠物名字”入口改为“宠物管理”，点击后进入图鉴。

### 4.2 宠物页入口

宠物展示页顶部改为工具栏：

- 左侧：`宠物图鉴 X/Y`
- 右侧：当前积分余额
- 存在未领养种类且当前养成宠物已满级时，图鉴入口显示“可领养”提示。
- “可领养”提示不依赖当前余额；余额不足在点击具体领养操作时提示。

### 4.3 图鉴布局

- iPad 竖屏：两列卡片。
- 手机：单列卡片。
- 当前两种宠物均展示在图鉴中，包括已领养和未领养状态。
- 两种宠物都已领养且满级后，页面显示“已集齐全部宠物”。

### 4.4 已领养卡片

卡片直接显示：

- 当前阶段对应的宠物图片
- 宠物名字
- 宠物种类
- 当前阶段名称
- “展示中”状态
- 「改名」操作
- 「设为展示」操作（当前展示宠物不重复显示）

图鉴不新增宠物详情页。改名使用弹窗；设为展示后直接返回宠物展示页。

### 4.5 未领养卡片

- 使用该种类第 1 阶段宠物蛋图片。
- 图片应用灰度效果，形成灰色剪影。
- 标注“未领养”。
- 当前养成宠物未满级时，只展示卡片，不显示领养操作。
- 解锁后显示「领养 100分」。
- 点击后按积分规则提示差额或打开命名弹窗。
- 宠物种类由用户所点击的卡片确定，命名弹窗不再重复选择种类。

## 5. 页面交互流程

### 5.1 第一只宠物满级

```text
喂食达到 1000 EXP
  → 播放满级进化效果
  → 停止心情自然衰减
  → 图鉴入口出现“可领养”提示
  → 图鉴中未领养宠物显示“领养 100分”
```

### 5.2 领养第二只

```text
进入宠物图鉴
  → 点击未领养宠物的“领养 100分”
  → 检查余额
    → 不足：提示还差 N 分
    → 足够：打开命名弹窗
  → 填写名字并确认
  → 再次检查余额
  → 扣除 100 分并创建宠物
  → 新宠物成为展示宠物
  → 返回宠物展示页
```

### 5.3 展示满级宠物

```text
在图鉴中对满级宠物点击“设为展示”
  → 返回宠物展示页
  → 显示满级宠物及互动功能
  → 隐藏喂食按钮
  → 若存在未满级宠物，显示“正在养成”快捷卡
```

### 5.4 集齐全部宠物

```text
小鸡和小兔均已领养且满级
  → 图鉴显示“已集齐全部宠物”
  → 保留改名、设为展示和互动
  → 不再显示领养操作
```

## 6. 数据与架构调整

### 6.1 Domain

展示状态落在宠物记录上，使用 `isDisplayed` 字段，不新建设置表。养成身份由「唯一未满级宠物」推导，不增加 `isRaising` 或 `raisingPetId`。

实现时必须保证：

- 一个 `childId` 最多只有一只展示宠物。
- 一个 `childId` 最多只有一只未满级宠物。
- 同一 `childId` 下宠物 `type` 不重复。
- `Pet.applyMoodDecay()` 对满级宠物不执行自然衰减。

### 6.2 Repository

当前 `findByChildId(childId).first()` 必须拆分为语义明确的接口：

- 查询当前展示宠物
- 查询当前养成宠物
- 查询用户全部宠物
- 按宠物 ID 查询
- 判断指定宠物种类是否已领养
- 原子切换展示宠物

不得继续依赖 IndexedDB 返回的第一条宠物记录决定当前宠物。

### 6.3 Service

`PetService` 需要覆盖以下用例：

- 获取展示宠物状态
- 获取养成中宠物
- 获取宠物图鉴列表
- 免费创建第一只宠物
- 校验并付费领养后续宠物
- 按宠物 ID 改名
- 设置展示宠物
- 对展示宠物执行抚摸互动
- 只对养成中宠物执行喂食

领养确认必须具备并发防护，并在 Service 层重复校验：

- 当前养成宠物是否满级
- 种类是否已经领养
- 是否存在其他未满级宠物
- 当前余额是否足够

### 6.4 Store

宠物 Store 至少需要管理：

- 当前展示宠物状态
- 当前养成宠物状态
- 全部宠物列表
- 图鉴加载状态
- 领养、改名、切换展示等 mutation 状态

首页只消费当前展示宠物；喂食操作只更新当前养成宠物和积分余额。

### 6.5 路由

新增路由常量：

```typescript
PET_COLLECTION: '/pet/collection'
```

底部宠物 Tab 当前使用 `/pet` 前缀匹配，因此进入 `/pet/collection` 后应继续保持选中；实现时需补充对应路由配置。

## 7. 数据库与备份兼容

### 7.1 IndexedDB 升级

- 当前数据库 schema 为 v6，实现时升级到 v7。
- 为 `pets` 表补充 `isDisplayed` 字段，并增加必要索引。
- 现有唯一宠物自动设为当前展示宠物。
- 现有宠物未满级时自动视为当前养成宠物。
- 现有宠物已满级时不再视为养成中宠物，并立即具备后续领养资格。

### 7.2 旧备份导入

- 旧版备份中宠物记录不含多宠物展示字段，导入时必须自动补齐。
- 如果旧备份只有一只宠物，将它设为展示宠物。
- 旧宠物是否可继续养成由其 `stage` 判定。
- 新版备份需要保存全部宠物及当前展示选择。
- 导入不能破坏现有 v1 备份兼容能力。

### 7.3 关键数据快照

第一只满级、第二只尚未领养时，`pets` 只有一行：该宠 `isDisplayed = true`，养成对象为空。首页和宠物页继续展示这只满级宠，图鉴入口出现「可领养」，不显示「正在养成」快捷卡。

两只均已领养且都满级时，`pets` 有两行，展示对象仍是 `isDisplayed = true` 的那只，养成对象为空。本期没有第三只宠物，图鉴显示「已集齐全部宠物」，不再出现领养。

## 8. 异常与反馈

- 余额不足：`积分不足，还差 N 分`
- 种类已拥有：`已经领养过这种宠物`
- 当前宠物未满级：`当前宠物满级后才能领养下一只`
- 存在未满级宠物：`请先把正在养成的宠物养到满级`
- 领养成功：`领养成功，快去和它打个招呼吧！`
- 改名成功：`宠物名字已更新`
- 设置展示成功后直接返回宠物页，不额外弹出阻断式确认。

所有错误反馈继续使用全局 `toast`；领养和改名弹窗必须复用 `BaseModal`。

## 9. 验收标准

1. 旧用户升级后原宠物、阶段、EXP、心情和名字不丢失。
2. 第一只宠物仍可免费创建。
3. 第一只未满级时，不能领养第二只。
4. 第一只满级后，图鉴入口出现“可领养”提示。
5. 余额不足 100 分时，点击领养能显示准确差额且不扣分。
6. 余额足够时，确认领养只扣除一次 100 分。
7. 同一种宠物不能重复领养。
8. 任意时刻最多只有一只未满级宠物。
9. 新领养宠物自动成为首页和宠物页展示对象。
10. 用户可以从图鉴切换展示任意已领养宠物。
11. 展示满级宠物时无喂食功能，但抚摸互动可用。
12. 满级宠物心情不再随时间自然下降。
13. 展示满级宠物且存在养成中宠物时，可通过快捷卡切回。
14. 每只宠物都可独立改名，允许重名。
15. 图鉴在 iPad 竖屏为两列，手机为单列。
16. 两种宠物都满级后显示“已集齐全部宠物”。
17. 导出再导入后，全部宠物、成长状态和展示选择保持不变。
18. 旧版备份仍可正常导入。

---

## 10. 本期不包含

- 重复领养同一种宠物
- 同时养成多只未满级宠物
- 删除、放生或归档宠物
- 领养积分明细或完整积分流水
- 宠物详情页
- 宠物排序
- 宠物换装、小游戏等新互动
- 第三只及以后的宠物种类

## 11. 实施任务拆分

按 T1 → T8 依次交付，每次只做一块。T3 可与 T4 并行，但不挡后续页面任务。

### T1. Domain：多宠物规则与模型

- **做什么**：`Pet` 增加 `isDisplayed`；满级不衰减心情；导出 `PET_ADOPTION_COST = 100`；补「是否满级 / 是否可继续养成」判断。
- **文件**：`src/domain/models/Pet.ts`、`src/domain/rules/PetGrowthRule.ts`
- **可验收**：满级宠物调用 `applyMoodDecay()` 心情不变；常量可被 Service 引用。
- **依赖**：无

### T2. Repository + IndexedDB v7

- **做什么**：废止 `findByChildId().first()`；补查询展示宠物、养成宠物、全部宠物、按 ID、按种类是否已领养、原子切换展示；schema 升到 v7；旧数据迁移（唯一宠物设为展示）。
- **文件**：`src/domain/repositories/IPetRepository.ts`、`src/infrastructure/database/repositories/DexiePetRepository.ts`、`src/infrastructure/database/DexieDatabase.ts`
- **可验收**：旧库升级后原宠物不丢，且自动成为展示宠物。
- **依赖**：T1

### T3. 备份导入导出兼容

- **做什么**：新备份保存全部宠物和展示选择；旧备份缺字段时自动补齐（单宠设为展示，养成资格看 `stage`）；不破坏现有 v1 备份。
- **文件**：`src/domain/repositories/IBackupAdapter.ts`、`src/infrastructure/storage/JsonBackupAdapter.ts`，必要时 `src/application/services/BackupService.ts`
- **可验收**：旧备份能导入；新备份再导入后展示选择不变。
- **依赖**：T2

### T4. PetService 用例

- **做什么**：覆盖第 6.3 节用例：展示 / 养成 / 图鉴、免费首养、付费续养（二次校验 + 并发锁 + `spendOnPet(100)`）、按 ID 改名、设展示、抚摸展示宠、只喂养成宠。满级不再加 EXP。
- **文件**：`src/application/services/PetService.ts`
- **可验收**：首只免费；未满级不能续养；同种类不能重复；确认领养只扣一次 100 分。
- **依赖**：T2（T3 可并行，不挡 Service）

### T5. Store + 路由骨架

- **做什么**：Store 管理展示宠、养成宠、全部宠物、图鉴加载、领养 / 改名 / 切换 mutation；首页继续只读展示宠。加 `ROUTES.PET_COLLECTION` 和 `/pet/collection` 空页，底部宠物 Tab 保持选中。
- **文件**：`src/presentation/hooks/usePetStore.ts`、`src/shared/constants.ts`、`src/App.tsx`、新建图鉴页面入口
- **可验收**：路由能进图鉴；Tab 仍选中宠物；首页不因 Store 改动报错。
- **依赖**：T4

### T6. 宠物展示页改造

- **做什么**：顶部工具栏（图鉴 X/Y + 积分；可领养提示不看余额）；满级隐藏喂食、保留抚摸；展示满级且存在养成宠时显示「正在养成」快捷卡。首只仍走现有创建表单。
- **文件**：`src/presentation/pages/Pet/index.tsx` 及相关子组件
- **可验收**：对应第 9 节验收 4、9、11、13。
- **依赖**：T5

### T7. 宠物图鉴页

- **做什么**：已领养 / 未领养卡片、改名弹窗（`BaseModal`）、领养命名弹窗、设为展示后回宠物页、手机单列 / iPad 竖屏两列、集齐文案、积分不足 toast。
- **文件**：新建 `src/presentation/pages/PetCollection/`，复用或抽离命名弹窗
- **可验收**：对应第 9 节验收 5–8、10、14–16。
- **依赖**：T5、T6（入口）

### T8. 设置入口收口

- **做什么**：设置页「宠物名字」改为「宠物管理」，进入图鉴；去掉设置页内联改名（改名只在图鉴）。
- **文件**：`src/presentation/pages/Settings/index.tsx`、`src/presentation/pages/Settings/PetNameEditor.tsx`
- **可验收**：设置只能进图鉴，不能直接改名。
- **依赖**：T7

整功能完成后再更新 `.cursor/context/` 项目知识库。
