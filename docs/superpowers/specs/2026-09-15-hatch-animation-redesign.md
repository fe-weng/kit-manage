# 宠物破壳动画重构设计

> 日期：2026-09-15  
> 状态：已实施
> 范围：宠物从 `EGG` 进化到 `HATCHED` 的演出

## 1. 背景

现有孵化动画将完整蛋 `stage-1-egg.png`、三张独立蛋壳碎片、SVG 裂纹和新宠物同时叠加。壳片会先在中心显现，再向外飞；完整蛋则延迟到 0.85 秒后才开始退出。破裂瞬间因此会看到完整蛋、重复蝴蝶结和三块不能严密拼合的壳片重叠。

`evo-shell-cracked.png` 不是原始素材的一部分。它在后续提交中被加入 `public` 和 `src/assets`，当前代码没有引用。本设计不依赖该图片。

## 2. 目标

- 用现有完整蛋、三张小兔壳片和刚孵化宠物完成连贯的破壳演出。
- 破裂冲击点清晰，不能出现完整蛋与三块壳片同时清晰可见的组合。
- 小鸡缺少壳片时自然降级，不显示假壳片，也不请求不存在的文件。
- 手机和平板共用同一时间轴，位移按旧蛋尺寸缩放。
- 清理重复、未使用和来源不明的壳素材。

## 3. 非目标

- 不修改喂食、经验或进化判定。
- 不修改其他三段进化动画。
- 不新增图片、第三方依赖、音效或庆祝文案。
- 不用 CSS 几何图形伪造小鸡壳片。

## 4. 视觉方案

采用“暖白闪光遮切 + 壳片爆开”。

闪光不是装饰，而是素材切换的遮挡层。完整蛋在闪光峰值隐藏；三张壳片只在该峰值出现并立即向不同方向飞散。它们不需要、也不允许先在中心拼成一颗裂开的整蛋。新宠物在同一冲击点开始出现，并保持在壳片后方。

### 4.1 图层顺序

从后到前：

1. 新宠物。
2. 完整蛋。
3. SVG 裂纹。
4. 暖白闪光。
5. 壳片。
6. 星光粒子。
7. 页面 vignette。

闪光下降前完整蛋必须已经隐藏。新宠物可以在闪光后半段透出，壳片始终位于新宠物前方。

### 4.2 时间轴

总时长为 1800 毫秒。

- `0–280ms`：完整蛋停止常规漂浮，左右轻晃并从 `scale 1` 蓄力到约 `1.04`。
- `280–360ms`：SVG 裂纹快速出现；暖白闪光开始扩散。
- `360ms`：唯一冲击点。
  - 完整蛋隐藏。
  - 有素材的壳片从各自起点出现并开始飞散。
  - 新宠物从 `opacity 0`、`scale 0.55`、`y 18` 开始弹出。
  - 星光粒子开始扩散。
- `360–950ms`：闪光消散；壳片完成飞行；新宠物放大到约 `1.06` 后回落到 `1`。
- `950–1400ms`：粒子衰减，新宠物稳定落位。
- `1400–1800ms`：保留完成帧，页面 vignette 退出。

动画期间继续拦截抚摸、喂食和页面点击；到 1800 毫秒后统一恢复。

## 5. 壳片运动

壳片的起点和终点以旧蛋展示尺寸 `fromSize` 为基准，不使用固定像素距离。

- 左片起点：中心左侧约 `0.22 × fromSize`，纵向接近中心；终点向左下移动约一个蛋宽，旋转约 `-40°`。
- 右片起点：左片镜像；终点向右下移动约一个蛋宽，旋转约 `40°`。
- 顶片起点：中心上方约 `0.28 × fromSize`；终点向上移动约一个蛋高，旋转约 `-10°`。

壳片容器仍需补偿 PNG 自带透明留白，显示尺寸使用 `1.15 × fromSize`。壳片在冲击点由透明变为可见，整个可见期持续约 600 毫秒。

## 6. 素材策略

以 `public/pets/<petType>/` 为唯一壳片来源，延续用户直接补充素材的方式。

保留：

- `public/pets/rabbit/evo-shell-left.png`
- `public/pets/rabbit/evo-shell-right.png`
- `public/pets/rabbit/evo-shell-top.png`

删除：

- `public/pets/rabbit/evo-shell-cracked.png`
- `src/assets/pets/rabbit/evo-shell-left.png`
- `src/assets/pets/rabbit/evo-shell-right.png`
- `src/assets/pets/rabbit/evo-shell-top.png`
- `src/assets/pets/rabbit/evo-shell-cracked.png`

`SHELL_SHARD_IMAGES` 继续作为显式能力登记表。路径通过 `import.meta.env.BASE_URL` 生成；禁止通过图片加载成功与否自动猜测素材是否存在。

每种宠物必须一次登记 `left`、`right`、`top` 三张素材。只放文件但不登记时，不播放壳片。

## 7. 小鸡降级与后续接入

小鸡未登记壳素材时仍使用相同的 1800 毫秒时间轴：

- 播放完整蛋蓄力。
- 播放裂纹、暖白闪光和粒子。
- 在冲击点隐藏完整蛋并弹出小鸡。
- 跳过壳片层，不显示 CSS 假壳片，不发起壳图片请求。

后续补齐三张小鸡素材后：

1. 将文件放入 `public/pets/chicken/`。
2. 在 `SHELL_SHARD_IMAGES.chicken` 一次登记三条路径。
3. 不修改时间轴和组件逻辑。

## 8. 代码设计

### 8.1 `evolutionTransition.ts`

- 增加 `HATCH_TIMELINE_MS`，集中保存总时长、冲击点、闪光结束、壳片结束和稳定帧时间。
- 将 hatch 总时长从 2500 毫秒调整为 1800 毫秒。
- hatch 揭晓点与统一冲击点保持一致。
- 其他 evolution kind 的时间参数保持不变。

### 8.2 `PetDisplay.tsx`

- 旧形态图片使用 `sizeMap[prevStage]`，新形态图片使用 `sizeMap[stage]`。
- hatch 换图采用同步模式，避免 `AnimatePresence mode="wait"` 在冲击点后额外等待旧图退出。
- 完整蛋的隐藏和新宠物的进入使用同一个 `HATCH_TIMELINE.impact`。
- 非 hatch 动画维持现有换图行为。

### 8.3 `EvolutionFx.tsx`

- 恢复 public URL 生成函数，并让 `SHELL_SHARD_IMAGES` 保存显式 URL。
- `HatchShards` 无登记时返回 `null`，保留闪光、裂纹和粒子。
- 重写三张壳片的相对起点、终点、透明度和旋转关键帧。
- 增加暖白径向闪光，峰值覆盖完整蛋切换。
- hatch 的裂纹、闪光、壳片和粒子全部引用 `HATCH_TIMELINE`，不保留互相独立的延迟魔法数。
- 随机值只负责粒子方向差异，不影响关键节拍。

### 8.4 `EvolutionOverlay.tsx`

- 继续只负责页面 vignette、点击拦截和动画结束回调。
- 使用更新后的 hatch 总时长。
- 不在 Overlay 中复制内部动画时间点。

## 9. 状态与异常边界

- `prevStage` 缺失时不播放壳片，以当前图片尺寸作为安全尺寸；正常进化流程不应进入该分支。
- 宠物类型未登记时按无壳片素材处理。
- 动画播放中重复点击喂食或抚摸仍由现有锁和 overlay 拦截。
- 组件卸载时清理揭晓和结束计时器。
- 不允许因单张图片加载失败而切换到半套壳片；构建和验收必须确认登记文件齐全。

## 10. 验证方案

项目没有现成自动化测试框架，本次不为动画单独新增依赖。

实施后执行：

1. TypeScript 与 Vite production build。
2. 在 390px 手机宽度检查小兔完整动画。
3. 在 744px 平板宽度检查位移与尺寸比例。
4. 检查小鸡无壳片降级动画。
5. 在约 280、360、500、950、1400 毫秒观察关键帧。
6. 检查动画期间交互被拦截，结束后恢复。
7. 检查 Network 中没有 `evo-shell-cracked.png` 请求，也没有小鸡壳片 404。

## 11. 验收标准

- 任意关键帧都没有完整蛋与三张壳片同时清晰可见。
- 蝴蝶结没有双影，底部花瓣不会与飞散壳片形成第二颗蛋。
- 小兔破壳能明确读出“蓄力、冲击、飞散、出现、稳定”。
- 小鸡没有壳素材时仍然自然，没有假色块或缺图。
- 手机和平板使用相同节奏，运动距离按旧蛋尺寸缩放。
- 孵化动画在 1800 毫秒后结束并恢复操作。
- 其他三种进化动画行为不变。
- public 与 src/assets 不再保留重复壳素材。

## 12. 风险与控制

- 三张壳片由独立图片生成，无法严密拼合。通过闪光遮切和分离起点避免暴露拼合问题。
- 1800 毫秒比原来的 2500 毫秒更短。完成帧保留 400 毫秒，避免显得突然结束。
- public 文件没有 TypeScript import 的构建期校验。通过显式三张登记和构建后的 Network 验收控制缺图风险。
- PWA 可能短时间显示旧缓存。部署验收时确认 service worker 完成更新；必要时关闭旧页面后重新打开。
